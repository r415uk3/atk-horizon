# ATK Horizon — Android-приложение для настройки наушников

Дата: 2026-10-19 · Статус: черновик на одобрение

## Зачем

Владелец наушников ATK Horizon (версия USB Type-C) настраивает их через ATK Hub web (hub.atk.pro): переключает пресеты и крутит эквалайзер. На телефоне сайт не работает (мобильный Chrome не поддерживает WebHID), а официальное Android-приложение ATK Audio Hub полностью на китайском. Нужно своё Android-приложение, которое делает то же, что Hub для Horizon, — на русском/английском и в дизайне в духе Apple (Liquid Glass).

Аудитория: сам автор (APK для себя); возможно, позже — открытый репозиторий на GitHub. Google Play не нужен.

## Цели

- Функционально повторить ATK Hub для Horizon (кроме прошивки — см. не-цели).
- Главное — пресеты и эквалайзер: они должны **гарантированно применяться**.
- Интерфейс RU + EN, дизайн «стекло» с темами Авто / Светлая / Тёмная.

## Не-цели

- iOS, Bluetooth, другие модели ATK.
- Аппаратный вариант Horizon **KTMicro** (PID `0x129F`) — у пользователя TTGK.
- Обновление прошивки (риск окирпичить; только показываем версию).
- Функции сверх Hub.
- Автозапуск приложения при подключении донгла/наушников (пользователь открывает сам).

## Анти-цели (провал, даже если «работает»)

- Эквалайзер не применяется или пресет не переключается, а UI показывает, что всё хорошо. Любое расхождение между тем, что отправили, и тем, что в устройстве, должно быть видно пользователю.

## Ограничения

- Устройство пользователя: Android 16. Наушники: ATK Horizon, VID `0x373B`, PID `0x120C` (вариант TTGK, чип CB1300), прошивка 0.9 — подтверждено скриншотом официального приложения.
- Официальное Android-приложение ATK подключается к этим наушникам без root → USB Host доступ к HID-интерфейсу из обычного приложения возможен.
- Протокол восстановлен по JS ATK Hub web 3.2.28 и **ещё не проверен на железе**.

## Решения

Решено с пользователем:
- Платформа — только Android.
- Пресеты и эквалайзер — ядро; остальные функции Hub для Horizon — тоже.
- Дизайн — вариант A (см. ниже), мягкий пастельный фон, темы Авто/Светлая/Тёмная.
- Языки — русский и английский.
- Обновления прошивки нет, только отображение версии.
- Приложение запускается вручную.
- Проект — git-репозиторий `~/atk-horizon`.

Решено мной (Claude), пользователь отдал выбор:
- Kotlin + Jetpack Compose, нативный `android.hardware.usb.UsbManager`, без React Native/Flutter.
- Язык интерфейса — по языку системы (без переключателя в приложении).
- Стекло: размытие через `RenderEffect`/`Modifier.blur` и/или библиотеку Haze (chrisbanes/haze), блики/преломление — AGSL `RuntimeShader`. Т.к. целевой Android 16, `minSdk` можно ставить 33 и не делать фолбэков для старых версий.

## Протокол (TTGK, PID 0x120C)

Источник: `.reference/demoMode.store-DQmSowxd.js` (минифицированный бандл hub.atk.pro, в git не коммитится). Ориентиры по байтовым смещениям: транспорт ~621277, enum команд и класс EQ-пакета до ~632000, математика коэффициентов ~627700–631000, контроллер Horizon `yu` ~632071, встроенные пресеты ~1030700, флаги функций Horizon ~1376234, логика UI эквалайзера ~1394500–1405000, чтение при подключении ~1487322. Общий HID-класс — `.reference/base-hid-device-Cgv5YaFg.js`.

### Транспорт
- HID output report, report ID `0x4B` (75), 63 байта данных, добивка нулями. Ответы — input reports.
- Байт 0 — направление: `0x01` запись, `0x80` чтение; байт 1 — команда; байт 2 — длина; далее payload.
- Ответ сопоставляется по эхо байта 0 (и команды). Таймаут 500 мс, 3 повтора.
- Записи EQ, фиксация коэффициентов и сохранение во флеш Hub шлёт **без ожидания ответа**.
- Рукопожатия, авторизации, контрольных сумм нет.

### Команды (используемые)
| Код | Назначение |
|---|---|
| `0x01` | Сохранить EQ во флеш |
| `0x02` / `0x03` | Смещение усиления ADC (микрофон) / DAC (воспроизведение), int16 = dB×256 |
| `0x04` | Сохранить смещения усиления |
| `0x09` | Записать/прочитать полосу EQ |
| `0x0A` | Применить коэффициенты EQ к регистрам |
| `0x0C` | Версия прошивки (чтение `80 0C 00`, ASCII в байтах 3–5) |
| `0x1B` | AI-шумоподавление микрофона (чтение `80 1B 00`, байт 3 = 1 вкл); Hub пишет без ожидания ответа и без сохранения во флеш |

Уточнения по коду Hub (проверено в бандле при ревью документа):
- Смещение усиления микрофона — это `0x02` (ADC gain offset, читается обратно), а не `0x1C` (Hub его не вызывает).
- `0x04` Hub не шлёт: после любого изменения DAC/ADC offset он шлёт `0x01`.
- В последовательности применения пресета DAC offset — текущий глобальный offset устройства, не значение из пресета.
- `0x17` (RestoreFactorySettings) в бандле определён, но Hub его не вызывает.

Остальные из enum (`0x05` erase flash, `0x0D` flash r/w, `0x17`, `0xFF` вход в загрузчик и т.п.) **не использовать** — опасны.

### Эквалайзер
- 8 полос, у каждой: тип (0 выкл, 1 lowshelf, 2 peak, 3 highshelf, 4 lowpass, 5 highpass), частота 20–20000 Гц, усиление −10…+10 dB шаг 0.1, Q 0.1–10.
- По умолчанию: 31, 62, 125, 250, 500, 1k, 2k, 4k Гц, Q 0.75, 0 dB, peak.
- Запись полосы (`0x09`), после report ID: `[0]=01 [1]=09 [2]=0x18 [3]=eqIndex(0) [4]=band 0–7 [5..6]=0 [7..26]=5×int32 LE коэффициентов [27..28]=fc u16 LE [29..30]=Q×256 u16 LE [31..32]=gain×256 int16 LE [33]=type [34]=gainOffset int8 [35]=eqNumber(0)`.
- Коэффициенты считает хост: biquad при fs = 96000, квантование ×2^30 с округлением, порядок b0, b1, b2, −a1, −a2. **Формулы для каждого типа фильтра портировать один-в-один из бандла** (около смещения 627700): там есть нестандартности — например, одна из shelf-реализаций игнорирует Q и использует фиксированный наклон 0.8, другая клэмпит параметры (gain ≤12, Q 0.5–5) и умножает gain на headroom 0.85. Какая реализация привязана к какому `filterType` — найти по фабрике `Pb.calculateByBytes`.
- Чтение полосы: `80 09 02 00 <band>`, ответ в формате записи.
- Применение пресета (как в Hub): 8× запись `0x09` → `01 0A 04 00 00 FF FF` → `01 03 02 lo hi` (DAC gain offset) → пауза ~1 с → `01 01` (сохранить во флеш).

## Функции и экраны

Мокап главного экрана (светлая/тёмная тема + настройки): `docs/design/mockup-main-screen.html`.

**Звук (главный).** Заголовок «Horizon», статус подключения, кнопка ⚙︎. Ряд «таблеток» пресетов (встроенные + пользовательские; пользовательские можно создать из текущей кривой, переименовать, удалить; встроенные удалить нельзя). Карточка с кривой АЧХ и 8 точками: перетаскивание по X — частота, по Y — усиление; тап — панель полосы (тип, точная частота, усиление, Q). Пресеты хранятся на телефоне; в устройстве — только активная кривая.

**Микрофон.** AI-шумоподавление вкл/выкл; смещение усиления микрофона.

**Устройство.** Модель, VID/PID, версия прошивки (только чтение); смещение громкости воспроизведения (DAC gain offset); «Сбросить настройки» с подтверждением — **мягкий сброс** (решение пользователя): записать пресет Default по схеме применения пресета, обнулить DAC и ADC gain offset, сохранить `0x01`, перечитать и проверить. Стирание флеша (`0x05`), как делает Hub, не используется.

**Настройки (⚙︎).** Тема Авто/Светлая/Тёмная (Авто = системная); ссылка на GitHub; версия приложения.

**Нет подключения.** Экран «Подключите ATK Horizon».

Навигация — плавающий стеклянный таб-бар: Звук / Микрофон / Устройство.

## Поведение «применилось ли»

- После применения пресета/полосы приложение читает полосы обратно (`80 09 …`) и сравнивает с отправленным (частота, Q, gain, тип; коэффициенты — побайтно). Расхождение или таймаут → явная ошибка в UI, и кривая показывает то, что реально в устройстве.
- При подключении — читаем текущие 8 полос, прошивку, шумоподавление, и UI отражает устройство, а не локальный кэш.
- Активный пресет определяется сравнением кривой из устройства с пресетами, как в Hub: fc точно, gain/Q с допуском 0.01, тип совпадает. Не совпало ни с одним — «Свой».
- Редактирование полосы — как в Hub: через 500 мс после последнего изменения шлём `0x09` → `0x0A` → DAC offset → пауза 1 с → `0x01`. (Моё дополнение: во время перетаскивания допустимо писать `0x09`+`0x0A` чаще для живого звука, но флеш — только по этой схеме.)
- Custom1 — встроенный неудаляемый пресет, не пользовательский слот.

## Риски и что проверить первым (spike на железе)

1. **Канал до HID.** Найти HID-интерфейс (usagePage 0x000C), отправить `80 0C 00` и получить версию «0.9». Варианты отправки: interrupt OUT endpoint, если есть; иначе control transfer SET_REPORT (`bmRequestType 0x21, bRequest 0x09, wValue 0x024B, wIndex = номер интерфейса`). Чтение: interrupt IN или GET_REPORT `0x014B`.
2. **Кнопки на проводе.** `claimInterface(force=true)` может отцепить ядерный HID-драйвер и сломать кнопки громкости/плей. **Решение пользователя: допустимо, пока приложение на переднем плане** — держим долгий claim, пока приложение открыто, и отпускаем его в `onStop` (чтобы кнопки вернулись, когда приложение свёрнуто). Живые записи при перетаскивании — да. Звук сам по себе ломаться не должен — это проверить.
3. **Разрешение USB.** Без intent-filter на `USB_DEVICE_ATTACHED` Android будет спрашивать разрешение при каждом подключении; если это раздражает — `device_filter.xml` с intent-filter, не делающий автозапуск (на усмотрение строителя, без автооткрытия).
4. **Коэффициенты.** Сверить, что прочитанные из устройства байты полосы (записанные официальным приложением) совпадают с нашими посчитанными для тех же параметров — лучший тест порта формул.
5. Ответы на «fire-and-forget» команды — что приходит в input report, не мешает ли это сопоставлению ответов.
